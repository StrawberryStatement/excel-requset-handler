# 系统交互与提示改造要求

本文档记录对代码和页面体验的改造要求，不属于需求管理运作规范。

## 1. 中文错误信息要求

所有错误、异常、提示必须使用中文，并满足三段式结构：

```text
发生了什么 + 为什么影响分析 + 用户应该怎么改
```

错误信息不应只写：

```text
Invalid file
Missing required columns
Duplicate key
```

应该写成：

```text
基准需求列表缺少必填列：云服务。系统无法判断需求归属的云服务，请在基准表中补充“云服务”列后重新上传。
```

## 2. 推荐错误文案

| 场景 | 用户提示 |
| --- | --- |
| 基准表缺少 FE 编号列 | 基准需求列表缺少必填列：FE编号。系统无法按内部需求编号汇总，请补充该列后重新上传。 |
| 基准表缺少云服务列 | 基准需求列表缺少必填列：云服务。系统无法判断需求归属的云服务，请补充该列后重新上传。 |
| 基准表 FE 重复 | 基准需求列表中存在重复 FE：{FE编号}。系统已继续分析并高亮异常，请确认应保留哪一行。 |
| 来源列表缺少云服务列 | 来源列表 `{文件名}` 缺少云服务列。请补充该列，或在上传前配置空值/默认值填充规则。 |
| 云服务为空 | 第 {行号} 行云服务为空。请补充云服务，或配置该字段的默认填充值。 |
| FE 和 RR 都为空 | 第 {行号} 行缺少 FE编号 和 RR编号。系统无法识别这条需求，请至少补充一个编号。 |
| 上传文件不是 Excel | 文件 `{文件名}` 不是可识别的 Excel 文件，请上传 `.xlsx` 或 `.xlsm` 文件。 |
| 表头重复 | 文件 `{文件名}` 存在重复表头：{字段名}。请修改重复列名后重新上传。 |
| 空值填充 JSON 错误 | 空值填充规则不是合法 JSON。请检查括号、引号和逗号格式。 |
| 评论模板为空 | 当前评论模板为空。请填写模板内容，或恢复默认模板后重试。 |
| 无可回刷评论 | 当前没有生成待回刷评论。可能是未选择评论字段，或所选字段在来源列表中没有值。 |

## 3. 异常等级展示

| 等级 | 含义 | 展示建议 |
| --- | --- | --- |
| 无 | 正常记录 | 默认样式。 |
| 信息 | 仅提示，不影响处理 | 蓝色或灰色提示。 |
| 提醒 | 需要关注，但不阻断 | 黄色高亮。 |
| 高优先级异常 | 需要人工确认 | 橙色高亮。 |
| 严重 | 数据基础错误或主键错误 | 红色高亮。 |

严重异常和高优先级异常默认不进入待回刷评论，除非未来增加人工确认放行能力。

## 4. 前端问号说明要求

所有相对复杂的功能项旁边必须提供一个小问号说明。

小问号应解释：

1. 这个字段或功能是干什么的。
2. 用户应该怎么填。
3. 填错会产生什么影响。
4. 给出一个简短示例。

问号内容应使用中文，避免技术术语堆叠。

## 5. 必须增加问号的页面项

| 页面项 | 问号说明建议 |
| --- | --- |
| 基准需求列表 | 从线上系统或内部主数据导出的基准表，用于作为比对和关联基础。至少需要 FE编号、云服务、需求标题。 |
| 来源列表 | 专项、服务或临时维护的需求列表。可以上传多份，系统会按 FE/RR/云服务关联。 |
| FE 列 | 内部 Feature 编号字段名。如果你的表头不是 FE编号，可以在这里改成实际列名。 |
| RR 列 | 外部需求编号字段名。如果来源需求来自客户或外部系统，通常需要填写 RR。 |
| 云服务列 | 需求承载的云服务字段名。该字段用于区分服务视角和专项视角，缺失会被标记为异常。 |
| 标题列 | 需求标题字段名，用于页面展示和人工确认。 |
| 我负责的云服务 | 用逗号填写你负责的服务，例如 A,B。大小写不敏感，用于生成“我负责的云服务需求”视图。 |
| 用于生成回刷评论的字段 | 这些字段会被拼进待回刷评论。例如：对齐结论、会议纪要、风险。未选择的扩展字段仍会导出，但不进入评论。 |
| 空值填充规则 JSON | 当某些列为空或缺失时，可以显式配置默认值。系统会保留原始数据，并记录填充说明。 |
| 评论目标 | 选择评论最终写到 FE、RR，还是 FE 和 RR 都写。 |
| 同步到一层关联对象 | 开启后，评论会同步给直接关联的 FE/RR，但不会继续递归扩散。 |
| 评论模板 | 用于生成回刷评论的文本格式。支持变量，例如 {{FE编号}}、{{RR编号}}、{{对齐结论}}。 |
| 下载需求汇总包 | 下载包含总览、FE视角、RR视角、待回刷评论、异常项和原始数据的 Excel 包。 |

## 6. 问号交互要求

1. 鼠标悬停或点击问号时展示说明。
2. 说明文案不应超过 120 字。
3. 移动端应支持点击展开。
4. 问号不应遮挡输入框。
5. 所有问号说明要可维护，建议集中放在前端配置对象中。

推荐前端配置结构：

```javascript
const helpTexts = {
  baseline: "从线上系统或内部主数据导出的基准表，用于作为比对和关联基础。至少需要 FE编号、云服务、需求标题。",
  sourceFiles: "专项、服务或临时维护的需求列表。可以上传多份，系统会按 FE/RR/云服务关联。",
  commentFields: "这些字段会被拼进待回刷评论。例如：对齐结论、会议纪要、风险。未选择的扩展字段仍会导出，但不进入评论。"
};
```

## 7. 页面与导出一致性要求

页面展示和导出包必须使用同一套字段语义。

要求：

1. 页面上看到的异常，导出包 `异常项` sheet 中必须能找到。
2. 页面上看到的待建 FE，导出包 `待建FE` sheet 中必须能找到。
3. 页面上看到的待回刷评论，导出包 `待回刷评论` sheet 和 `sync_plan.json` 中必须能找到。
4. 页面筛选不应改变后端计算结果，只影响当前展示。
5. 导出包必须保留原始行数据，便于追溯。

## 8. 后续代码改造建议

1. 建立统一错误码和中文错误文案映射。
2. 后端异常返回结构增加 `code`、`message`、`suggestion`。
3. 前端按异常等级使用统一颜色和样式。
4. 小问号说明集中配置，不分散写死在 HTML 中。
5. 所有复杂配置项必须有示例。
6. 页面上传失败时，应保留用户已填写的配置项，避免重新输入。
