# 需求管理运作规范

## 1. 目标

本规范用于约束外部需求、内部需求、专项需求列表、服务需求列表和线上需求管理系统之间的协作方式。

核心目标：

1. 外部客户或外部协作方提出的需求，必须使用 `RR编号` 跟踪。
2. 内部研发交付、上线排期、状态跟踪，必须使用 `FE编号` 跟踪。
3. `RR编号` 和 `FE编号` 可以一对一、一对多、多对一关联，但不能混用语义。
4. Excel 需求列表用于阶段性对齐，线上需求管理系统仍然是最终事实源。
5. 所有回刷线上系统的结论，必须先生成待确认清单，再由人工确认后回刷。
6. 所有错误、异常、页面说明必须使用中文，并能指导用户修改。

> 说明：本文中的 FE 指内部 Feature 编号。如果实际系统中字段名叫 F1，需要在字段映射中统一配置，但业务语义仍按 FE 处理。

## 2. 编号管理规则

### 2.1 RR 编号

`RR编号` 表示外部需求编号。

适用场景：

1. 客户提出需求。
2. 外部项目、外部系统、外部协作方提出需求。
3. 需要面向外部承诺、解释、追踪的需求。

规则：

| 规则 | 要求 |
| --- | --- |
| 外部需求必须有 RR | 外部来源需求进入内部管理前，应先有 `RR编号`。 |
| RR 可以暂时没有 FE | 表示内部还未拆解或未创建 FE，系统标记为 `待建FE`。 |
| 一个 RR 可以拆多个 FE | 大需求拆成多个内部交付项，标记为 `RR拆分`。 |
| 多个 RR 可以合并到一个 FE | 多个外部诉求由同一个内部能力承载，标记为 `RR合并`。 |
| RR 不直接代表研发交付 | 研发排期、上线、状态收敛必须落到 FE。 |

### 2.2 FE 编号

`FE编号` 表示内部 Feature 编号，是内部研发交付和线上系统回刷的主要对象。

适用场景：

1. 内部规划需求。
2. 研发排期与交付跟踪。
3. 上线状态跟踪。
4. 对齐结论回刷。
5. 与 RR 建立关联关系。

规则：

| 规则 | 要求 |
| --- | --- |
| 内部交付必须有 FE | 只要进入研发排期或上线跟踪，就必须有 `FE编号`。 |
| FE 可以没有 RR | 内部规划需求或研发直接承接的需求，可以标记为 `无外部RR`。 |
| FE 是回刷优先主键 | 能定位到 FE 时，优先按 FE 生成回刷评论。 |
| FE 不应被多个来源共同管理 | 同一 FE 出现在多个来源列表时，系统标记为 `多来源共同管理`，默认按高优先级异常处理。 |
| FE 与云服务归属应稳定 | 同一 FE 出现多个云服务时，系统标记为 `云服务冲突`。 |

## 3. 需求列表类型

当前工具不强制用户使用固定模板，但所有来源列表必须能映射到统一字段模型。

常见来源：

| 来源 | 说明 |
| --- | --- |
| 基准需求列表 | 从线上系统或内部主数据导出的基准表。 |
| 专项需求列表 | 某个专项维度维护的需求列表，专项名默认来自文件名。 |
| 服务需求列表 | 某个云服务维度维护的需求列表。 |
| 临时需求列表 | 会议、项目、客户沟通后临时整理的需求列表。 |

统一要求：

1. 来源列表可以有自定义扩展列。
2. 来源列表不要求来自本工具模板。
3. 来源列表中的扩展列必须保留，不强制合并为一个字段。
4. 系统需要展示来源列表名称和原始行号，便于追溯。

## 4. 字段规范

### 4.1 基准需求列表字段

基准需求列表用于表示当前线上系统或内部主数据中的已知需求。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| FE编号 | 必填 | 内部 Feature 编号。基准表中允许检测到重复，但必须高亮为 `基准重复FE`。 |
| RR编号 | 选填 | 外部需求编号。内部规划需求可以为空。 |
| 云服务 | 必填 | 需求承载的云服务。缺失列或空值都必须提示。 |
| 需求标题 | 必填 | 需求的简要描述。 |
| 状态 | 建议必填 | 线上或内部当前状态。 |
| 排期 | 建议必填 | 当前计划排期，例如 `2026Q2`。 |
| 负责人 | 建议必填 | 当前内部负责人或研发接口人。 |
| 优先级 | 选填 | P0/P1/P2 或团队内部优先级。 |
| 最后更新时间 | 选填 | 用于识别数据新旧，不作为默认 diff 字段。 |
| 备注 | 选填 | 只保留，不默认作为结构化字段回刷。 |

基准表约束：

1. 缺少 `FE编号`、`云服务`、`需求标题` 中任一列，应阻断分析并提示用户补列。
2. `FE编号` 重复不阻断分析，但必须在预览和异常项中高亮。
3. `云服务` 缺失或为空必须标记为严重异常。
4. 基准表中的状态、排期、负责人只作为比对基准，不直接被来源列表覆盖。

### 4.2 来源需求列表字段

来源需求列表用于表达专项、服务、项目经理或临时场景的需求管理信息。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| FE编号 | 条件必填 | 内部已有 FE 时必须填写。没有 FE 但有 RR 时进入 `待建FE`。 |
| RR编号 | 条件必填 | 外部需求必须填写。内部规划需求可以为空。 |
| 云服务 | 必填 | 缺少列或空值都必须提示。可以通过显式空值填充规则补齐。 |
| 需求标题 | 建议必填 | 用于人工识别和导出阅读。 |
| 状态 | 选填 | 可以进入回刷评论，但不直接结构化更新线上系统。 |
| 排期 | 选填 | 可以进入回刷评论，但不直接结构化更新线上系统。 |
| 负责人 | 选填 | 可以进入补充信息。 |
| 对齐结论 | 选填 | 推荐作为回刷评论核心字段。 |
| 会议纪要 | 选填 | 推荐作为回刷评论补充字段。 |
| 风险 | 选填 | 推荐作为回刷评论补充字段。 |
| 客户影响 | 选填 | 推荐作为回刷评论补充字段。 |
| 备注 | 选填 | 推荐作为回刷评论补充字段。 |

来源列表约束：

1. `FE编号` 和 `RR编号` 不能同时为空。
2. 来源列表缺少 `云服务` 列，应提示为数据问题。
3. 如果用户配置空值填充规则，系统可以补齐空字段或虚拟列，但必须保留原始数据。
4. 来源列表新增的所有扩展列必须被保留，并在导出包中并排展示。
5. 同一 FE 出现在多个来源列表时，默认认为需要人工确认。

### 4.3 待建 FE 清单字段

当 RR 有值但 FE 为空，且系统无法唯一识别候选 FE 时，应进入 `待建FE` 清单。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| RR编号 | 必填 | 外部需求编号。 |
| 云服务 | 必填 | 用于创建或匹配 FE。 |
| 需求标题 | 建议必填 | 辅助创建 FE。 |
| 来源列表 | 必填 | 追溯来源。 |
| 来源行号 | 必填 | 追溯原始 Excel 行。 |
| 创建后FE编号 | 回填必填 | 新建 FE 后回填。 |
| 处理状态 | 必填 | 默认 `待建FE`，后续可改为 `已创建FE`。 |
| 备注 | 选填 | 人工处理说明。 |

回填匹配建议：

1. 优先使用 `RR编号 + 云服务` 匹配。
2. 其次使用 `FE编号 + RR编号` 匹配。
3. 再其次使用 `FE编号 + 云服务` 匹配。

### 4.4 待回刷评论清单字段

待回刷评论清单用于人工确认后写入线上系统。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 目标类型 | 必填 | `FE`、`RR`。 |
| 目标ID | 必填 | FE 编号或 RR 编号。 |
| FE编号 | 选填 | 当前记录关联的 FE。 |
| RR编号 | 选填 | 当前记录关联的 RR。 |
| 云服务 | 必填 | 需求承载服务。 |
| 来源列表 | 必填 | 评论内容来源。 |
| 评论内容 | 必填 | 按模板生成。 |
| 状态 | 必填 | 默认 `待确认`。 |

## 5. 关联与异常规则

| 场景 | 系统识别 | 处理方式 |
| --- | --- | --- |
| FE 和 RR 都存在 | 正常关联 | 按 FE 聚合，保留 RR。 |
| RR 有值，FE 为空 | 待建 FE 或 FE候选 | 能唯一匹配时标记 `FE候选`，否则标记 `待建FE`。 |
| FE 有值，RR 为空 | 无外部 RR | 允许存在，表示内部规划或研发直接承接。 |
| FE 和 RR 都为空 | 缺主键 | 严重异常，默认不进入回刷。 |
| 一个 RR 对多个 FE | RR拆分 | 允许存在，但需要展示关联关系。 |
| 多个 RR 对一个 FE | RR合并 | 允许存在，但需要展示关联关系。 |
| 同一 RR 在不同来源对应不同 FE | RR关联异常 | 高亮提示人工确认。 |
| 同一 FE 对多个云服务 | 云服务冲突 | 严重异常，默认不进入回刷。 |
| 同一 FE 出现在多个来源列表 | 多来源共同管理 | 高优先级异常，默认不进入回刷。 |
| 基准表 FE 重复 | 基准重复FE | 严重异常，但不阻断分析。 |
| 来源列表缺少云服务列 | 缺云服务列 | 严重异常，提示补列或显式配置默认值。 |

## 6. 回刷评论规则

### 6.1 回刷原则

1. MVP 不直接更新线上系统结构化字段。
2. 状态、排期、负责人、风险、结论等对齐结果，统一以评论形式沉淀。
3. 评论必须先生成待确认清单。
4. 人工确认后才能调用线上系统 API。
5. 严重异常和高优先级异常默认不进入回刷清单。

### 6.2 用于生成回刷评论的字段

页面上的“用于生成回刷评论的字段”表示：哪些 Excel 列会被拼进评论模板。

示例配置：

```text
对齐结论,会议纪要,风险,客户影响,备注
```

含义：

1. 系统会读取这些列的值。
2. 有值的字段会进入评论内容。
3. 未填写的字段不会输出空行。
4. 未被选择的扩展列仍会保留在导出包里，但不会进入回刷评论。

推荐默认值：

```text
对齐结论,会议纪要,风险,客户影响,备注
```

### 6.3 评论模板

默认评论格式：

```text
【需求对齐结论】
来源列表：{{来源列表}}
云服务：{{云服务}}
关联FE：{{FE编号}}
关联RR：{{RR编号}}
对齐时间：{{对齐时间}}
对齐对象：{{对齐对象}}

【对齐结论】
{{对齐结论}}

【补充信息】
{{补充信息}}

【回刷说明】
本评论由需求列表关联工具根据用户确认结果生成。
```

模板要求：

1. 支持默认模板。
2. 支持新增、编辑、删除、自定义保存。
3. 第一版模板保存在浏览器 `localStorage`。
4. 后续如接入后端存储，需要支持个人模板、团队模板、系统默认模板。

### 6.4 评论目标

评论目标支持：

| 目标 | 说明 |
| --- | --- |
| FE | 只给内部 FE 写评论。 |
| RR | 只给外部 RR 写评论。 |
| FE + RR | 同时给当前记录关联的 FE 和 RR 写评论。 |

同步到一层关联对象：

1. 默认关闭。
2. 开启后，只同步一层直接关联对象。
3. 不允许递归扩散，避免评论被写到过多关联需求上。

## 7. 中文错误信息规范

### 7.1 基本原则

所有错误、异常、提示必须使用中文，并满足三段式结构：

```text
发生了什么 + 为什么影响分析 + 用户应该怎么改
```

错误信息不应只写：

```text
Invalid file
Missing required columns
Duplicate key
```

应该写成：

```text
基准需求列表缺少必填列：云服务。系统无法判断需求归属的云服务，请在基准表中补充“云服务”列后重新上传。
```

### 7.2 推荐错误文案

| 场景 | 用户提示 |
| --- | --- |
| 基准表缺少 FE 编号列 | 基准需求列表缺少必填列：FE编号。系统无法按内部需求编号汇总，请补充该列后重新上传。 |
| 基准表缺少云服务列 | 基准需求列表缺少必填列：云服务。系统无法判断需求归属的云服务，请补充该列后重新上传。 |
| 基准表 FE 重复 | 基准需求列表中存在重复 FE：{FE编号}。系统已继续分析并高亮异常，请确认应保留哪一行。 |
| 来源列表缺少云服务列 | 来源列表 `{文件名}` 缺少云服务列。请补充该列，或在上传前配置空值/默认值填充规则。 |
| 云服务为空 | 第 {行号} 行云服务为空。请补充云服务，或配置该字段的默认填充值。 |
| FE 和 RR 都为空 | 第 {行号} 行缺少 FE编号 和 RR编号。系统无法识别这条需求，请至少补充一个编号。 |
| 上传文件不是 Excel | 文件 `{文件名}` 不是可识别的 Excel 文件，请上传 `.xlsx` 或 `.xlsm` 文件。 |
| 表头重复 | 文件 `{文件名}` 存在重复表头：{字段名}。请修改重复列名后重新上传。 |
| 空值填充 JSON 错误 | 空值填充规则不是合法 JSON。请检查括号、引号和逗号格式。 |
| 评论模板为空 | 当前评论模板为空。请填写模板内容，或恢复默认模板后重试。 |
| 无可回刷评论 | 当前没有生成待回刷评论。可能是未选择评论字段，或所选字段在来源列表中没有值。 |

### 7.3 异常等级

| 等级 | 含义 | 是否默认进入回刷 |
| --- | --- | --- |
| 无 | 正常记录 | 是 |
| 信息 | 仅提示，不影响处理 | 是 |
| 提醒 | 需要关注，但不阻断 | 可进入 |
| 高优先级异常 | 需要人工确认 | 否 |
| 严重 | 数据基础错误或主键错误 | 否 |

## 8. 前端问号说明规范

### 8.1 总体要求

所有相对复杂的功能项旁边必须提供一个小问号说明。

小问号应解释：

1. 这个字段或功能是干什么的。
2. 用户应该怎么填。
3. 填错会产生什么影响。
4. 给出一个简短示例。

问号内容应使用中文，避免技术术语堆叠。

### 8.2 必须增加问号的页面项

| 页面项 | 问号说明建议 |
| --- | --- |
| 基准需求列表 | 从线上系统或内部主数据导出的基准表，用于作为比对和关联基础。至少需要 FE编号、云服务、需求标题。 |
| 来源列表 | 专项、服务或临时维护的需求列表。可以上传多份，系统会按 FE/RR/云服务关联。 |
| FE 列 | 内部 Feature 编号字段名。如果你的表头不是 FE编号，可以在这里改成实际列名。 |
| RR 列 | 外部需求编号字段名。如果来源需求来自客户或外部系统，通常需要填写 RR。 |
| 云服务列 | 需求承载的云服务字段名。该字段用于区分服务视角和专项视角，缺失会被标记为异常。 |
| 标题列 | 需求标题字段名，用于页面展示和人工确认。 |
| 我负责的云服务 | 用逗号填写你负责的服务，例如 A,B。大小写不敏感，用于生成“我负责的云服务需求”视图。 |
| 用于生成回刷评论的字段 | 这些字段会被拼进待回刷评论。例如：对齐结论、会议纪要、风险。未选择的扩展字段仍会导出，但不进入评论。 |
| 空值填充规则 JSON | 当某些列为空或缺失时，可以显式配置默认值。系统会保留原始数据，并记录填充说明。 |
| 评论目标 | 选择评论最终写到 FE、RR，还是 FE 和 RR 都写。 |
| 同步到一层关联对象 | 开启后，评论会同步给直接关联的 FE/RR，但不会继续递归扩散。 |
| 评论模板 | 用于生成回刷评论的文本格式。支持变量，例如 {{FE编号}}、{{RR编号}}、{{对齐结论}}。 |
| 下载需求汇总包 | 下载包含总览、FE视角、RR视角、待回刷评论、异常项和原始数据的 Excel 包。 |

### 8.3 问号交互要求

1. 鼠标悬停或点击问号时展示说明。
2. 说明文案不应超过 120 字。
3. 移动端应支持点击展开。
4. 问号不应遮挡输入框。
5. 所有问号说明要可维护，建议集中放在前端配置对象中。

推荐前端配置结构：

```javascript
const helpTexts = {
  baseline: "从线上系统或内部主数据导出的基准表，用于作为比对和关联基础。至少需要 FE编号、云服务、需求标题。",
  sourceFiles: "专项、服务或临时维护的需求列表。可以上传多份，系统会按 FE/RR/云服务关联。",
  commentFields: "这些字段会被拼进待回刷评论。例如：对齐结论、会议纪要、风险。未选择的扩展字段仍会导出，但不进入评论。"
};
```

## 9. 页面与导出一致性要求

页面展示和导出包必须使用同一套字段语义。

要求：

1. 页面上看到的异常，导出包 `异常项` sheet 中必须能找到。
2. 页面上看到的待建 FE，导出包 `待建FE` sheet 中必须能找到。
3. 页面上看到的待回刷评论，导出包 `待回刷评论` sheet 和 `sync_plan.json` 中必须能找到。
4. 页面筛选不应改变后端计算结果，只影响当前展示。
5. 导出包必须保留原始行数据，便于追溯。

## 10. 后续待讨论事项

以下内容当前先按默认规则处理，后续可以继续讨论：

1. 是否要强制所有外部 RR 在创建 FE 前先进入一个待分解池。
2. `状态`、`排期`、`负责人` 是否永远只以评论形式回刷，还是未来允许结构化字段更新。
3. `多来源共同管理` 是否允许用户手动确认后进入回刷。
4. `基准重复FE` 是否只按 FE 判断，还是需要结合 `云服务`、`RR编号` 进一步判断。
5. 空值填充规则是否需要支持按文件名、来源类型、云服务分别配置。
6. 评论模板未来是否需要团队级共享和审批。
