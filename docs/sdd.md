# 软件设计说明

本文档描述 V2 需求列表关联与梳理工作台的设计。文档统一使用中文。

## 1. 产品目标

最终目标：

```text
让专项维度和服务维度的需求状态统一。
让不同人维护的来源列表收敛成同一套可确认结果。
让确认后的状态和结论最终能回刷到线上需求管理系统。
```

核心能力：

1. 上传基准需求列表和多个来源列表。
2. 根据 FE、RR、云服务建立关联。
3. 支持专项视角、产品视角、RR 视角、异常视角。
4. 支持来源列表名称和弱来源类型。
5. 支持我负责的云服务配置。
6. 支持空值填充规则。
7. 支持选择进入待回刷评论的字段。
8. 支持 FE、RR、FE+RR 三类评论目标。
9. 支持可选同步评论到一层直接关联对象。
10. 导出收敛的 `需求汇总包.xlsx`。
11. 支持评论模板默认值、自定义、删改和保存。
12. 支持从表格内容识别评论变量。
13. 保留内部系统 API 接入点，但 MVP 不直接写系统。

## 2. 核心约束

1. FE 是内部系统回刷的优先编号。
2. RR 是外部需求跟踪编号。
3. FE 和 RR 都可能为空，但不能同时为空。
4. 云服务是必需维度。
5. 缺少云服务列是文件问题，不能静默通过。
6. 空值填充必须由用户显式配置。
7. 专项默认来自来源列表文件名。
8. 来源列表类型不作为强约束，第一版可以统一为 `需求列表`。
9. 严重异常默认不进入回刷。
10. 回刷系统前必须人工确认。
11. 罕见关系不进入主流程，但必须可检测、可高亮、可导出。
12. 状态回刷仍以评论形式沉淀，不做结构化字段更新。
13. RR 有独立 API，但当前项目只预留接口，不访问内部系统。
14. 不做模板下载，不要求用户按本工具模板准备 Excel。
15. 对齐时间、对齐对象从表格内容识别，不作为独立页面字段。

## 6. 空值填充规则

规则结构：

```text
来源列表
字段名
触发条件：列存在但为空 / 列不存在时创建虚拟列
默认值
```

要求：

1. 不能静默填充。
2. 必须记录填充来源。
3. `原始行数据` 中保留填充前状态。
4. `异常项` 中保留缺列或空值被处理的提示。

## 7. 待建 FE 闭环

待建 FE 触发条件：

```text
RR 有值
FE 为空
无法通过 RR 找到唯一 FE
```

系统导出 `待建FE` sheet。

后续通过上传 RR-FE 映射表回填：

```text
RR编号
云服务
创建后FE编号
备注
```

匹配优先级：

```text
1. RR编号 + 云服务
2. FE编号 + RR编号
3. FE编号 + 云服务
```

回填后系统重新分析，将记录从 `待建FE` 更新为 `FE已补齐`。

## 8. 回刷评论模型

评论目标支持：

```text
FE
RR
FE + RR
```

默认只给当前对象写评论。

可选项：

```text
同步评论到一层直接关联对象
```

规则：

```text
当前对象是 FE：同步到直接关联 RR。
当前对象是 RR：同步到直接关联 FE。
只扩展一层，不递归。
```

`多来源共同管理` 属于高优先级异常，默认不进入回刷评论，用户确认后才允许进入。

状态、排期等字段即使发生变化，MVP 也不直接以结构化字段更新线上系统。统一生成评论，由用户确认后回刷。

评论格式固定为：

```text
【需求对齐结论】
来源列表：{来源列表名称}
云服务：{云服务}
关联FE：{FE编号，可为空}
关联RR：{RR编号，可为空}
对齐时间：{生成时间或用户选择时间}
对齐对象：{用户填写，可为空}

【对齐结论】
{对齐结论字段内容}

【补充信息】
风险：{风险}
会议纪要：{会议纪要}
客户影响：{客户影响}
备注：{备注}

【回刷说明】
本评论由需求列表关联工具根据用户确认结果生成。
```

缺失字段不输出空行。

模板能力：

```text
默认模板
新增模板
编辑模板
删除模板
保存模板
选择任务使用模板
```

第一版模板保存：

```text
浏览器 localStorage
```

原因：

```text
当前 MVP 没有用户体系和数据库。
后端保存会引入模板存储、权限、版本和迁移问题。
```

后续后端保存计划：

```text
数据结构：
模板ID
模板名称
模板内容
创建人
更新时间
是否默认
版本号

API：
GET /api/comment-templates
POST /api/comment-templates
PUT /api/comment-templates/{id}
DELETE /api/comment-templates/{id}
POST /api/comment-templates/{id}/set-default
```

未来接入用户体系后，需要区分：

```text
个人模板
团队模板
系统默认模板
```

模板变量由评论变量识别模块填充。

建议模块：

```text
backend/app/commenting/
  template_engine.py
  extractors.py
  model_extractor.py
  schemas.py
```

第一版同时使用字段名匹配和内容关键字匹配：

```text
按字段名识别：对齐时间、会议时间、沟通时间、对齐对象、参与人、沟通对象
按内容关键字识别：和xx对齐、与xx确认、xx会议、xx评审、xx沟通
```

后续可以在 `model_extractor.py` 中接内部模型。

## 10. 内部系统 API 预留

线上系统交互模块独立预留在：

```text
backend/app/integrations/
```

当前重点文件：

```text
backend/app/integrations/internal_system.py
```

后续内网可拆分：

```text
backend/app/integrations/
  internal_system.py
  feature_client.py
  requirement_client.py
  auth.py
  schemas.py
```

建议接口：

```python
get_feature(fe_id: str)
add_feature_comment(fe_id: str, comment: str)
get_requirement(rr_id: str)
add_requirement_comment(rr_id: str, comment: str)
```

Excel 解析、关联分析和评论生成模块不直接依赖内部系统 API。

当前开发环境不能访问内部系统。接口只预留适配层，后续在内网通过 MiniMax 或人工补全具体 API 调用。
