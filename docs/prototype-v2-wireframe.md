# V2 原型说明

本文档用于对齐“需求列表关联与梳理工作台”的原型和业务规则。当前阶段只讨论清楚原型，不进入实现。

## 1. 终极目标

这个工具的终极目的有两个。

第一，支持 **专项维度和服务维度的需求管理**：

```text
专项视角：看一个专项里 A、B、C、D 多个云服务的需求推进。
服务视角：看我负责的 A、B 云服务在不同专项、不同来源列表中的需求推进。
```

第二，支持 **专项维度和服务维度的需求列表统一**：

```text
不同人维护的几张来源列表，最终要收敛到同一套需求状态和对齐结论。
确认后的结果需要能够回刷到线上需求管理系统。
```

因此系统主流程必须围绕：

```text
识别同一需求
统一状态
暴露差异
人工确认
回刷线上系统
```

罕见关系要能检测和高亮，但不能让它们成为主流程。

## 2. 业务理解

你的角色有两类：

1. 你是 A、B 云服务的产品经理，需要梳理自己负责云服务下的需求。
2. 你也是专项 1、专项 2 的产品经理，需要梳理专项内的全部需求。

一个专项可能包含 A、B、C、D 多个云服务。C、D 不一定归你负责，但专项推进时也需要看。

系统需要支持两条主线：

```text
专项需求梳理
我负责的产品需求梳理
```

## 3. 术语约定

界面不要使用：

```text
PM Excel

PM 扩展字段
```

推荐使用：

```text
专项需求列表
来源列表
来源列表数
来源列表扩展字段
云服务
我负责的云服务
专项需求梳理
产品需求梳理
需求汇总包
```

## 4. 核心对象

| 对象 | 说明 |
|---|---|
| FE | 内部研发 feature 编号，优先用于内部系统回刷 |
| RR | 外部需求编号，用于客户需求跟踪 |
| 云服务 | 承载需求的服务，例如 A、B、C、D |
| 专项 | 跨服务项目或专项，默认从来源列表文件名提取 |
| 来源列表 | 上传的 Excel 文件，可以是专项列表、服务列表、会议对齐列表等 |
| 来源列表类型 | 标记来源列表的业务类型，保持通用 |
| 对齐结论 | 可能回刷到系统评论里的内容 |
| 空值填充规则 | 对某些字段的空值或缺失字段显式设置默认值 |

## 5. FE / RR 需求来源场景

### 5.1 FE 和 RR 都存在

说明：

```text
外部 RR 需求已经和内部 FE 建立关联。
```

处理：

```text
优先按 FE 合并。
保留 RR 关联。
校验云服务是否一致。
```

### 5.2 RR 存在，FE 为空

分两种情况。

第一种：内部已有 FE，只是当前来源列表没有填。

```text
RR-001 -> 可以在基准列表或其他来源列表找到唯一 FE-101
```

处理：

```text
标记 FE候选。
黄色高亮。
不静默补齐，由用户确认。
```

第二种：内部还没有 FE，需要拆给研发。

```text
RR-002 -> 找不到任何 FE
```

处理：

```text
按 RR 聚合。
标记 待建FE / 待拆FE。
进入专项梳理视图。
默认不进入 FE 侧回刷。
```

### 5.3 FE 存在，RR 为空

说明：

```text
内部自己规划的需求，或者研发已经用 FE 跟踪，但外部没有单独提 RR。
```

处理：

```text
按 FE 正常合并。
标记 无外部RR。
不是严重异常。
```

### 5.4 FE 和 RR 都为空

处理：

```text
严重异常。
红色高亮。
不参与自动合并。
不进入默认回刷。
```

## 6. FE / RR 关联关系

系统不能只选一个主键，而要同时维护 FE 视角和 RR 视角。

推荐关联优先级：

```text
1. FE 精确匹配
2. RR 辅助匹配
3. FE + 云服务用于异常校验
4. RR + 云服务用于待建 FE 分组和回填
```

### 6.1 一个 RR 对多个 FE

场景：

```text
外部客户提了一个大 RR，内部拆成多个 FE 给研发做。
```

处理：

```text
标签：RR拆分
专项视角按 RR 聚合展示
FE 视角按 FE 展开
不是错误，但需要可见提示
```

### 6.2 多个 RR 对一个 FE

场景：

```text
多个外部客户提出类似公共需求，内部用一个 FE 聚合实现。
```

处理：

```text
标签：RR合并
FE 详情里展示所有关联 RR
回刷 FE 评论时保留关联 RR 信息
```

### 6.3 同一个 RR 在不同来源列表里对应不同 FE

这个场景不常见，不作为主流程设计重点。

处理：

```text
按 RR 聚合提示。
如果多个 FE 都在基准列表中存在，标记 RR拆分待确认。
如果部分 FE 不在基准列表中，标记 RR关联异常。
默认进入异常视图，不在主表中强打扰。
```

### 6.4 同一个 FE 在不同来源列表里对应不同云服务

处理：

```text
严重异常。
红色高亮。
标签：云服务冲突。
不进入默认回刷。
```

### 6.5 同一个 FE 来自多个来源列表

这个场景也不常见，应作为高亮问题处理。

原因：

```text
两个专项同时管理同一个需求的概率不大。
出现这种情况，可能说明需求被重复纳入专项、专项边界不清，或者来源列表填写有误。
```

处理：

```text
标签：多来源共同管理
级别：高优先级异常
颜色：橙色或红色
默认展示并导出
默认不进入待回刷评论
用户确认后才允许进入回刷
```

详情页并排展示各来源列表扩展信息，不自动覆盖。

## 7. 异常和高亮规则

| 场景 | 级别 | UI 提示 | 默认处理 |
|---|---|---|---|
| FE 和 RR 都为空 | 严重 | 红色，`缺主键` | 不合并，不回刷 |
| RR 有值，FE 为空，且能按 RR 找到唯一 FE | 提醒 | 黄色，`FE候选` | 用户确认后可关联 |
| RR 有值，FE 为空，且找不到 FE | 提醒 | 黄色，`待建FE` | 按 RR 梳理，不回刷 FE |
| FE 有值，RR 为空 | 信息 | 灰色/蓝色，`无外部RR` | 按 FE 正常合并 |
| 一个 RR 对多个 FE | 信息/提醒 | 蓝色或黄色，`RR拆分` | 展示聚合关系 |
| 多个 RR 对一个 FE | 信息 | 蓝色，`RR合并` | 展示聚合关系 |
| 同 RR 对不同 FE，无法判断是否正常拆分 | 提醒 | 黄色，`RR拆分待确认` | 进入异常视图 |
| 同 FE 出现在多个来源列表 | 高优先级异常 | 橙色/红色，`多来源共同管理` | 确认后才允许回刷 |
| 同 FE 对不同云服务 | 严重 | 红色，`云服务冲突` | 阻断默认回刷 |
| FE 不在基准列表 | 提醒 | 黄色，`基准外FE` | 用户确认 |
| 基准列表 FE 重复 | 严重 | 红色，`基准重复FE` | 先修基准 |
| 来源列表修改基准字段 | 提醒 | 单元格黄色，`基准字段变更` | 保留基准值 |
| 缺少云服务列 | 严重 | 红色，`缺云服务列` | 需要用户处理 |
| 云服务为空 | 严重/提醒 | 红色或黄色，`云服务为空` | 可用空值填充规则处理 |

颜色规则：

```text
红色：阻断默认回刷，需要先处理
橙色：高优先级异常，需要确认后才能回刷
黄色：需要确认，但可进入梳理
蓝色：结构性关系提示，不一定是问题
灰色：信息提示
```

## 8. 字段配置和空值填充

建议字段：

```text
FE编号
RR编号
云服务
需求标题
```

规则：

```text
FE 和 RR 可以为空，但不能同时为空。
云服务是关键字段。缺少云服务列应认为文件有问题。
```

空值填充要做成通用能力：

```text
字段 [云服务] 为空时填充为 [A服务]
字段 [优先级] 为空时填充为 [P2]
字段 [来源系统] 为空时填充为 [手工导入]
```

扩展规则：

```text
如果列存在但单元格为空：按规则填充默认值。
如果列不存在：标记缺列问题；用户可以显式选择“创建虚拟列并填默认值”。
```

原则：

```text
不能静默通过。
必须让用户知道原始数据缺列或空值被处理过。
原始行数据 sheet 里要保留处理前状态。
```

## 9. 来源列表元数据

专项不是 Excel 固有列。

默认规则：

```text
专项 = 来源列表文件名去掉扩展名
```

来源列表类型不作为重点能力。第一版可以弱化为：

```text
需求列表
```

如果确实需要分类，最多保留少量固定选项：

```text
需求列表
会议对齐列表
其他
```

但这些类型只用于筛选和展示，不影响核心合并规则。

设计原则：

```text
来源列表本身不是从本工具统一产出的。
它通常是内部系统导出后，经过不同人加工形成的不同形态。
本工具的目标是汇总、关联、对齐，而不是要求大家以后从本工具模板重新开始维护。
```

因此不做模板下载，不要求用户按本工具模板准备 Excel。

必要能力应该是：

```text
字段映射
空值填充规则
异常提示
原始行追溯
```

## 10. 待回刷评论字段选择

字段不能写死。页面需要提供字段选择：

```text
[x] 对齐结论
[x] 会议纪要
[x] 风险
[ ] 客户影响
[ ] 内部备注
```

默认建议：

```text
自动勾选来源列表新增字段。
用户可以取消。
基准字段变更不默认进入评论，但可以在详情里追加。
```

评论按来源列表分块：

```text
[专项1需求列表]
关联RR: RR-001
云服务: A
对齐结论: 本周进入开发
风险: 依赖接口冻结

[服务A需求列表]
客户影响: 客户A要求保留旧入口
```

## 11. 评论模板和关键字识别

`对齐对象`、`对齐时间` 不作为独立页面字段处理。

原因：

```text
这些信息通常已经体现在来源列表的某些列里，例如对齐结论、会议纪要、备注等。
系统应该从表格内容里识别，而不是要求用户重复填写。
```

### 11.1 识别方式

第一版同时做字段名匹配和内容关键字匹配：

```text
按字段名识别：对齐时间、会议时间、沟通时间、对齐对象、参与人、沟通对象
按内容关键字识别：和xx对齐、与xx确认、xx会议、xx评审、xx沟通
```

后续可以预留模型识别能力：

```text
输入：来源列表行数据 + 已选评论字段
输出：结构化评论变量
```

模型可以来自内部模型，例如 MiniMax。

### 11.2 模块边界

评论变量识别能力独立成模块，避免和 Excel 解析、内部系统 API 耦合。

建议目录：

```text
backend/app/commenting/
  template_engine.py       # 评论模板渲染
  extractors.py            # 规则识别
  model_extractor.py       # 预留模型识别
  schemas.py               # 评论变量结构
```

### 11.3 评论模板

系统提供默认模板，但必须支持用户自定义。

能力：

```text
查看默认模板
新增模板
编辑模板
删除模板
保存模板
选择当前任务使用的模板
```

第一版保存策略：

```text
保存在浏览器本地 localStorage。
```

原因：

```text
后端保存需要引入模板存储、用户隔离、模板版本、权限和迁移策略。
当前 MVP 没有用户体系和数据库，先放浏览器本地更低成本。
```

后续后端保存计划：

```text
新增模板表或配置文件存储。
模板字段：模板ID、模板名称、模板内容、创建人、更新时间、是否默认、版本号。
API：创建模板、更新模板、删除模板、查询模板、设置默认模板。
如果未来接入用户体系，需要区分个人模板和团队模板。
```

模板变量示例：

```text
来源列表
云服务
FE编号
RR编号
对齐时间
对齐对象
对齐结论
风险
会议纪要
客户影响
备注
```

默认模板：

```text
【需求对齐结论】
来源列表：{{来源列表}}
云服务：{{云服务}}
关联FE：{{FE编号}}
关联RR：{{RR编号}}
对齐时间：{{对齐时间}}
对齐对象：{{对齐对象}}

【对齐结论】
{{对齐结论}}

【补充信息】
{{补充信息}}

【回刷说明】
本评论由需求列表关联工具根据用户确认结果生成。
```

渲染规则：

```text
变量为空时，该行不输出。
补充信息按用户选择字段生成。
模板支持删改保存。
```

## 12. 回刷评论目标

FE 和 RR 有关联，但也是相互独立的对象。评论目标不能只支持 FE。

页面支持：

```text
仅 FE
仅 RR
FE + RR
```

默认行为：

```text
只给当前选中的 FE 或 RR 添加评论。
```

可选增强：

```text
[ ] 同步评论到一层关联对象
```

勾选后：

```text
当前对象是 FE：同时给与该 FE 直接关联的 RR 添加评论。
当前对象是 RR：同时给与该 RR 直接关联的 FE 添加评论。
```

限制：

```text
只扩展一层直接关联关系。
不递归扩散。
不跨越二级关联。
```

示例：

```text
RR-001 -> FE-101, FE-102

当前在 RR-001 上写评论：
默认只写 RR-001。
勾选后同时写 RR-001、FE-101、FE-102。

当前在 FE-101 上写评论：
默认只写 FE-101。
勾选后同时写 FE-101、RR-001。
不会继续扩散到 FE-102。
```

## 13. 待建 FE 工作流

触发条件：

```text
RR 有值
FE 为空
无法通过 RR 找到唯一 FE
```

需求汇总包中单独生成：

```text
待建FE
```

建议字段：

```text
RR编号
云服务
需求标题
来源列表
来源列表类型
专项名称
业务背景
建议拆分说明
创建后FE编号
处理状态
备注
```

闭环：

```text
导出待建FE
相关同学在内部需求管理系统创建 FE
导入 RR-FE 映射表
系统重新分析
状态从 待建FE 更新为 FE已补齐
进入 FE 视角和待回刷评论
```

回填匹配建议：

```text
优先：RR编号 + 云服务 -> 创建后FE编号
辅助：FE编号 + RR编号
辅助：FE编号 + 云服务
```

MVP 不直接创建 FE。

## 16. 评论格式

回刷评论要用于后续对齐和追责，因此格式需要固定。

系统提供默认格式：

```text
【需求对齐结论】
来源列表：{来源列表名称}
云服务：{云服务}
关联FE：{FE编号，可为空}
关联RR：{RR编号，可为空}
对齐时间：{生成时间或用户选择时间}
对齐对象：{用户填写，可为空}

【对齐结论】
{对齐结论字段内容}

【补充信息】
风险：{风险}
会议纪要：{会议纪要}
客户影响：{客户影响}
备注：{备注}

【回刷说明】
本评论由需求列表关联工具根据用户确认结果生成。
```

说明：

```text
对齐结论是核心字段。
其他字段作为补充信息。
缺失字段不输出空行。
用户可以新增、编辑、删除、保存评论模板。
模板变量由规则识别或模型识别填充。
```

## 18. 已确认结论

1. 服务字段名使用 `云服务`。
2. “我负责的云服务”在页面上选择。
3. `专项` 默认来自来源列表文件名，不作为 Excel 必选列。
4. `专项负责人` 不进入 MVP。
5. FE 缺失但 RR 存在时，按 RR 聚合并高亮提示。
6. FE 有值但 RR 为空时，按 FE 正常处理，并提示 `无外部RR`。
7. 同一个 FE 对应不同云服务时，判定严重异常。
8. 同一个 FE 来自多个来源列表时，作为高优先级异常处理。
9. 多个来源列表给同一个 FE 的扩展信息并排展示。
10. 待回刷评论字段必须在页面可选择，不写死。
11. 来源列表类型要通用，不只支持专项需求列表。
12. 缺少 `云服务` 列是文件问题，不能静默通过。
13. 可以支持通用空值填充规则，包括显式创建虚拟列并填默认值。
14. `待建FE` 需要单独 sheet，并支持后续导入 RR-FE 映射形成闭环。
15. 评论目标支持 FE、RR、FE+RR。
16. 默认只给当前 FE 或 RR 提交评论；可选勾选后同步到一层直接关联对象。
17. `RR拆分待确认` 和 `多来源共同管理` 都不是常见主流程，应进入异常/高亮流程。
18. 来源列表类型弱化，第一版可以只叫 `需求列表`。
19. 状态字段回刷仍以评论形式沉淀，不做结构化字段更新。
20. 线上系统中 RR 有独立 API，当前项目只预留接口，不访问内部系统。
21. 不做模板下载，不要求用户按本工具模板准备 Excel。
22. 回刷评论格式需要固化，核心是对齐结论，用于减少后续扯皮。
23. 对齐对象和对齐时间不做独立页面字段，从表格内容中识别。
24. 评论模板必须支持默认模板、自定义、删改和保存。
25. 评论变量识别第一版同时做字段名匹配和内容关键字匹配，后续预留内部模型识别。
26. 评论模板第一版保存在浏览器 localStorage；后续再扩展后端保存。
